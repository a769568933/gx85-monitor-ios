# GX85 Monitor 0.2 功能升级设计草案

状态：用户已于 2026-10-15 在当前聊天确认。本文记录已确认的目标行为，不代表功能已经完成或通过 GX85 真机验证。

## 用户目标

在已能接收 GX85 实时画面的 iPhone App 上，修复遥控快门没有实际动作、取景不居中、底部信息压缩画面的问题；加入照片/视频操作、快门速度、光圈、ISO、点按对焦、相机相册和向 iPhone 导出媒体。继续采用接近 iPhone 原生相机的黑色界面，优先保证完整、大幅的实时取景，支持竖屏和两个横屏方向。

“IOS”按 ISO 感光度理解。相机切到视频拍摄模式时，主按钮应跟随变成录像按钮；App 也提供显式的照片/视频操作选择，避免固件不报告模式时无法操作。选择录像操作不宣称能够遥控转动机身模式拨盘。

## 已有证据和尚未确认的内容

- 用户诊断记录显示，三次 `capture` 均返回直接 `result=ok`；用户确认相机完全没有快门动作。这不足以证明已经生成照片，也不足以单独确定未对焦、相机模式、卡状态或快门按下/释放流程中的哪一项是根因。
- 当前拍摄流程只发送 `capture`，不读取拍摄前后状态，也没有录像分支。
- 当前健康检查读取状态后丢弃字段，且不记录正常的状态正文，缺少定位上述故障的证据。
- 当前 `safeAreaInset(edge: .bottom)` 会给提示条腾出空间，缩小 CameraView 的 GeometryReader，截图与此一致。
- 当前横屏由取景区域和固定 96 点侧栏组成，取景只居中于剩余空间；安全区也可能造成整个屏幕上的视觉偏移。
- JPEG 的适配计算本身是等比居中，修复重点是稳定父布局、明确屏幕中心和控件覆盖关系。
- 电脑目前没有 192.168.54.x 的相机网络接口，本阶段不能直接对用户 GX85 发起真机验证。

## 拟实现的交互

### 1. 稳定的监看布局

以整个屏幕的中心作为画面的水平、垂直中心，按源画面比例完整显示，不拉伸、不裁切。取景占满可用屏幕，控制层、参数层和提示层覆盖在画面上方，不改变取景的计算尺寸。

横屏主快门靠右，参数以紧凑条目显示；竖屏主快门靠下。控件遵守安全区，避免刘海、灵动岛和 Home 指示条。全屏监看隐藏常规控件，只保留退出入口。照片和视频构图比例不同造成的黑边属于正常适配。

提示使用覆盖式浮层，自动消失并支持关闭；长错误可展开查看。任何提示、导出进度、参数选择或对焦框均不得推动或缩放实时画面。遮挡控件上的触摸不能穿透到对焦层。

### 2. 快门和录像状态

连接后读取相机状态与能力，持续同步照片/视频模式、录制开关、可操作状态和卡状态。状态无法确认时显示“状态未确认”，不能编造已经拍成或正在录像。

照片操作包含：拍摄前检查可操作状态；在相机确实处于自动对焦且需要时执行单次对焦；发送一次拍照动作；依据设备能力处理快门释放；查询后续状态。不能因为 HTTP 200 或 `ok` 就报告“照片已保存”。相机可提供的新文件信息、计数或写卡活动用于增强确认；证据不足则报告“指令已接受，拍摄结果待确认”。失败、等待对焦、存储卡异常和被机身操作占用分别显示。

快门命令不自动重发。兼容分支必须由明确的命令拒绝或能力信息触发，不能在结果未知时换一种方式再拍一遍。对焦失败不擅自切换 MF，也不关闭机身的对焦优先设置。

主按钮在照片操作下为白色快门；视频操作下为红色圆形，录制确认后为红色停止方块并显示计时。使用 `video_recstart` / `video_recstop`，以相机回报确认开始和停止，避免仅根据本地点击切换。录制中禁用照片操作切换、相册和会冲突的命令。断连后标记录制状态未知，重连先查询，不擅自停止录像或再次开始。

相机拨盘模式优先同步到界面。优先使用已验证的状态/设置字段；若需要从 UDP 元数据读取，解析必须检验包结构和长度，不能对所有固件盲用固定偏移。未知模式保留显式操作选择，并在诊断中记录无法识别的值。

### 3. 快门速度、光圈、ISO

在紧凑参数条展示当前数值，点按后展开相机允许的选项。选项从能力/菜单回复取得，发送相机原始协议值，不能把光圈协议分数误当成实际 F 值。

根据 P/A/S/M、视频模式和镜头能力限制可修改项。不可修改的项目保留当前值，并解释“当前模式由相机自动控制”等原因。设置后重新读取确认，不先把界面改成未被相机接受的值。参数查询失败不应让已经正常工作的监看连接重启。

### 4. 点按对焦

仅对实际图像矩形内的点按发送对焦指令，忽略黑边和控制按钮。把点按位置减去黑边偏移，再换算为相机坐标；横竖屏、4:3、16:9 和全屏都使用同一套变换。

点按后显示对焦位置框；未取得合焦结果前仅表示请求位置，不能用绿色假装合焦。MF 或相机当前 AF 模式不支持位置移动时明确提示，不触发拍照。已知兼容的触摸命令按相机能力选择，失败不自动触发触摸快门。

### 5. 相机相册和导出

相册指相机存储卡内容，支持分页缩略图、照片/视频标识、单项预览和多选导出。首次打开时进入明确的浏览状态，按相机要求切换回放，暂停监看恢复策略，避免相册与实时监看争抢相机模式；退出后恢复拍摄和视频流。录像中不能进入相册。

通过相机的 ContentDirectory/媒体目录查询原文件和缩略图资源。服务地址由相机描述取得，并限制在用户连接的同一相机；在描述不可发现时，提供可诊断的已知端点兼容尝试，不能依赖某一台相机的 MAC 路径。

导出取相机提供的原始资源，默认支持实际可读取的 JPEG 和 MP4。以临时文件流式下载，展示进度、失败和取消；逐项处理，避免把整段视频读入内存。请求照片库“仅添加”权限后保存到 iPhone 照片；同时提供保存到“文件”入口。仅在完整下载和系统保存成功后报告成功；失败不得把缩略图冒充原片。

RAW、AVCHD、4K 视频、4K 连拍和后对焦文件存在 GX85 无线传输限制。不能保证所有格式都能无线导出。若相机确实提供可下载的原文件资源，可尝试下载并按系统支持程度保存到照片或文件；若只提供预览或不提供原件，必须标注“相机未提供此格式的无线原文件”，不能显示虚假的导出成功。视频不会在本版本中转码。

下载不修改、不删除相机原文件。相册保留分页、缩略图缓存和有界下载任务；断连、离开页面、取消下载或进入后台时释放资源，清理本次临时文件。

## 实现边界

- 协议层新增类型化的相机状态、能力/菜单、拍摄结果、媒体条目和 ContentDirectory 解析；所有 XML 禁止外部实体，限制正文大小并校验解析结果。
- 控制请求继续串行发送；拍摄、录像、参数设置、对焦和回放切换由同一个会话协调，避免健康检查和恢复任务穿插进关键流程。
- 媒体下载使用独立且受限的传输通道，仍校验同一相机地址与重定向；不更改现有 Wi-Fi 单播接收的有界队列原则。
- CameraSession 拆分拍摄控制、状态同步和相册生命周期职责，不把全部新逻辑塞入一个视图或一个大类。
- 保持 iOS 16 最低版本；新增仅添加照片库的权限说明，不申请不必要的照片库读取权限。
- 无相机时只显示连接引导或明确标记的测试夹具。测试截图不能冒充真机连接、录像或媒体导出成功。

## 验证与验收

1. 复现旧布局：覆盖式提示前后，取景矩形位置和大小完全相同；屏幕中点与画面中点一致。验证竖屏、横屏两方向、全屏、4:3/16:9、长提示和大字体。
2. 协议测试覆盖：嵌套 XML、缺失/未知状态、拒绝设置、模式切换、拍摄无确认、录像开始/停止超时、元数据包短包/未知版本；不得因未知拍摄结果重复快门。
3. 对焦测试覆盖黑边、边缘、控件遮挡和旋转后的坐标映射；框颜色不伪造合焦状态。
4. 相册测试覆盖 SOAP/DIDL 双层 XML、分页、媒体原件/缩略图区分、恶意外部资源 URL、取消、断连、内存边界、照片库拒绝权限和系统保存失败。
5. 在 GitHub 的 macOS 构建环境运行核心测试和 iPhone 模拟器测试，导出竖/横屏真实测试截图及新的未签名 ARM64 IPA。必须标明模拟器使用的测试数据。
6. GX85 真机验收：照片模式点击后有实际快门动作并生成新文件；切到视频模式按钮跟随，开始/停止录像与相机一致；参数读写、点按对焦、相册浏览、JPEG 和可传输 MP4 导出逐项核对。真机未确认的项目在发布记录中保留“待验证”，不能仅以编译通过声称修复。
