# GX85 Monitor：iPhone 第一版设计规格

日期：2026-10-13

状态：用户已于 2026-10-13 确认本规格，包含原生相机风格、大画面与横竖屏要求；源代码和工程已制作，苹果平台运行与真机验证待执行。交付状态见 ../../VALIDATION.md。

## 目标与已知条件

用户希望用 iPhone 连接松下 DMC-GX85，实时监看并遥控拍照，改善原厂 App 的卡顿、断连和恢复体验。用户只有 Windows，没有可用的 Mac。用户进一步明确：UI 参考 iPhone 原生相机，监看画面尽量做大，同时支持横版和竖版。现有工作目录没有已有产品工程或 Git 仓库。

第一版交付目标是独立的 iPhone 原生 App 工程、云端编译工作流、测试资料和中文安装说明。可安装包必须经过云端编译才能产生，随后需要签名并在用户手机验证。不能把源代码、模拟画面或未经编译的工程称为已可用 App。

默认支持 iOS 16 及以上；这是设计假设，手机系统较旧时需在实现前调整。照片保存在相机存储卡。第一版不自动下载照片。

## 方案选择

采用 Swift / SwiftUI 原生 App，使用系统网络和图像解码能力，无第三方运行时依赖。理由是可以直接处理 UDP 取景数据、应用生命周期和画面显示，且减少安装包和依赖维护。

备选方案是跨平台 App 加原生 UDP 模块，同样需要苹果编译和签名流程，并增加桥接和构建依赖。当前只有 iPhone 需求，因此暂不采用。

普通网页无法直接承担此相机所需的 UDP 接收；若使用网页，仍需额外电脑服务作为中转，不符合直接拿手机监看拍照的目标。

Windows 交付路线：准备 GitHub Actions macOS 构建工作流，编译 iPhone 真机架构，打包未签名 IPA；用户使用 AltStore Classic / AltServer 在 Windows 上签名并安装。工作流只输出构建产物，不上传 App Store，不自动发布 Release。上传代码到 GitHub 或实际运行云端任务属于后续操作，需要有用户选定的仓库和账号访问条件。

使用免费 Apple ID 侧载需要定期刷新签名，通常为七天。Apple 账号登录由用户在安装工具中自行完成，工程、工作流和 App 均不保存 Apple 密码。云端编译的可用额度取决于用户 GitHub 账号。侧载兼容性和首次安装是否成功必须在用户当前手机上确认。

## 第一版范围

1. 中文连接引导：在 GX85 开启“遥控拍摄与查看”，在 iPhone 设置中加入相机 Wi-Fi，返回 App，允许本地网络访问，并在相机上确认首次连接。
2. 连接地址可修改并保存；默认 `192.168.54.1`。不依赖广播发现、不读取 Wi-Fi 密码、不自动切换系统 Wi-Fi。
3. 实时监看，保持画面比例，支持横屏和竖屏及隐藏控制区的全屏监看；正常拍摄页只显示精简的连接状态，实际接收帧率及距最后一帧的时间放入诊断页。无画面时给出可执行的连接提示，不显示伪造的相机画面。
4. 快门按钮。一次用户操作最多发送一次拍照指令；区分“相机已接受指令”“相机拒绝”“结果未知”。第一版不把指令接受等同于照片已成功写卡。
5. 前台连接保活、画面停滞检测、有限次数自动恢复、手动重连和手动断开。
6. 诊断页：连接阶段、HTTP 回应结果、数据包/有效帧统计和最近错误。日志有条数上限，可以由用户主动导出用于真机排查。

触摸对焦、曝光参数调整、录像、相册下载、LUT、峰值对焦和多机控制不属于第一版验收范围。在连接和快门稳定后，再根据 GX85 真机支持情况扩展。

## 界面与操作流程

暂定名称 GX85 Monitor。

视觉参考 iPhone 原生相机：纯黑背景、白色环形大快门、简洁的图标控件和少量黄色状态强调。沿用其直观的拍摄层级，不添加 GX85 第一版尚不支持的镜头倍率、视频模式或照片缩略图入口。

取景区域优先获得空间。根据实际解码画面的宽高比，用 aspect-fit 计算可用区域内的最大完整画面；不拉伸、不裁去构图边缘。若手机与相机画面比例不同，以黑边保留完整画面，不以裁切制造“满屏”。不在拍摄界面常驻卡片、大标题、说明文字或帧率面板。

竖版布局：顶部为精简状态和设置入口，中部为尽可能宽大的取景区域，下方为紧凑控制区，白色快门居中，连接操作与全屏入口置于两侧。控制区使用约 120–136 pt 高度，其余可用高度全部交给取景；手机安全区额外处理。

横版布局：取景区域占据左侧和中间，右侧使用约 88–104 pt 宽的窄控制区，快门位于中间，连接和设置入口在上下方。顶部不增加独立的大工具栏。支持向左、向右两种横屏；控件避开刘海、灵动岛和底部手势区。按钮触摸范围至少 44 × 44 pt。

提供全屏监看入口，隐藏拍摄控制区，让取景使用整块可用屏幕；保留一个小的退出入口。全屏同样维持完整画面比例。隐藏快门期间不允许通过不可见区域触发拍摄。

旋转手机只调整布局，不断开网络、不重新握手、不重启相机视频流。画面方向尊重图像自身方向信息，不因为布局旋转而再次旋转像素。设置与诊断通过独立面板打开，不挤占主取景区域。

未连接时显示三步引导和连接按钮。正在握手时显示“正在连接”；需要相机确认时明确显示“请在相机上允许连接”。已接收有效画面才显示“监看中”。画面超过两秒没有更新时标记“画面已暂停”，不让用户把旧画面误认为当前画面。

快门只在当前控制会话有效且没有待完成快门操作时启用。控制连接仍有效但取景短暂暂停时可拍照；完全断连或正在重建会话时禁用。拍照后暂时停流不会立即被判定为整个相机断连。

## 相机通信

这些是依据第三方协议资料提出的兼容实现路径，不是松下公开保证的开发接口。GX80 的资料不能直接当作本用户 GX85 已验证的结果。

控制层使用 HTTP 请求 `/cam.cgi`。由独立请求构造器生成参数并正确编码；每个请求设置有限超时。使用无缓存、无蜂窝回退的会话，避免后台请求和无限请求堆积。

握手阶段发送 `accctrl / req_acc`，处理允许、等待确认、拒绝和异常回应。客户端使用持久化的自身标识和名称，不沿用示例中的其他设备身份。依据回应格式兼容逗号文本和 XML。拒绝或无法识别的回应必须记录并停止进入假“已连接”状态。

握手成功后读取 `getstate`，在录制模式启动实时流。先绑定本机 UDP 端口，再通过 `startstream` 告知相机目标端口；默认端口 49152，可配置以便兼容排查。确保绑定错误不会继续启动一个无法接收的监看会话。

遥控拍照候选指令为 `mode=camcmd&value=capture`。快门使用串行控制通道；超时不重试，显示“拍摄结果未知，请检查相机”，以免重复拍摄。手动断开后尽力发送停流命令并关闭本地资源。

## 数据与模块边界

- `CameraEndpoint`：本地相机地址、UDP 端口、输入校验；第一版仅接受合法 IPv4 地址和有效端口。
- `LumixCommandClient`：请求生成、有限超时、回应解析和错误分类，不管理 UI 或解码。
- `LiveViewReceiver`：绑定 UDP、限制来源地址、收包及关闭资源，不执行相机控制命令。
- `JPEGFrameAssembler`：剥离非图像数据、定位 JPEG 边界、限制缓存、丢弃损坏或不完整帧。独立于手机 UI，可用合成数据做测试。
- `LatestFrameDecoder`：最多一个解码任务和一个待处理新帧；新帧覆盖待处理旧帧。解码失败丢弃该帧并记录统计。
- `CameraSession`：连接状态、生命周期、保活和恢复，阻止重复连接和过期任务覆盖新会话。
- SwiftUI 视图：只显示会话状态及有效图像，并将用户操作交给会话层。

数据路径：相机 UDP → 接收器 → 有效 JPEG 帧 → 单任务解码 → 主线程更新画面。网络接收、帧处理和解码不在主线程执行。

JPEG 帧组装设置 2 MiB 上限及有限的未完成帧存活时间。对跨数据包边界、包前附加数据和损坏数据设计明确的丢弃行为。没有证据支持任意乱序分片的可靠重建；不拼凑未经验证的厂商分包协议，真机遇到不兼容格式时根据诊断数据调整解析器。

## 稳定性与生命周期

连接状态包括：未连接、连接中、待相机确认、控制就绪、监看中、恢复中和失败。状态变化均归属于一个会话代次，取消后的旧请求不能改变新会话。

初始保活周期两秒，使用状态读取作为健康检查。连续三次健康检查失败触发会话恢复。HTTP 控制健康但画面超过三秒未更新时先尝试一次重新启动视频流，再依据后续控制回应决定是否重建整个会话。拍照操作期间及其后短暂窗口暂停取景停滞恢复，窗口结束后重新评估。

自动恢复按 1、2、4、8 秒退避，最多四次；失败后提示检查相机 Wi-Fi，提供手动重连。系统 Wi-Fi 已切走时不能承诺 App 自动切回；相机退出遥控模式时提示用户重新开启。

监看活动时保持屏幕点亮。进入后台时取消循环、停止解码并关闭接收器，尽力停流；返回前台仅在用户仍期望连接时重新建立会话。主动断开会取消自动恢复。

## iOS 权限与工程配置

声明本地网络用途，文案解释“连接 GX85 并接收实时监看画面”。使用直接单播，不引入需要额外授权的广播发现或多播功能。

相机使用明文 HTTP，工程必须配置允许相机本地 HTTP 所需的 ATS 设置，并在安装说明解释它仅用于连接相机。优先采用能支持数字 IP 的最小配置；具体配置需在 iOS 真机检查。App 不加入照片库权限，因为第一版不下载或保存照片到 iPhone。

输出完整 Xcode 工程和共享构建方案；云端工作流使用明确的 macOS runner，检查当前 Xcode 版本。真机 IPA 为未签名构建产物，必须经安装工具签名，不能直接点开安装。

## 验证与交付判定

本地可以检查文件结构、工程配置、命令及回应解析设计。苹果平台的编译和模拟器测试必须在 macOS 执行；没有云端结果时，交付说明必须明确标注“尚未完成 Xcode 编译验证”。

有意义的自动测试覆盖：URL 参数编码、合法与非法相机地址、文本/XML 回应成功及拒绝、JPEG 垃圾前缀/截断/跨边界/超限恢复、快门超时不重发、会话取消后不复活、控制健康时单独恢复取景。

真机验证按顺序记录：

1. 首次连接、相机许可与本地网络权限流程。
2. 连续监看至少 15 分钟，记录有效帧率、停帧、恢复次数及明显内存增长。
3. 连续点击快门 20 次，核对相机照片数量，确认没有由 App 重试造成的重复照片。
4. 切换后台再返回、离开相机 Wi-Fi 再加入、相机退出遥控模式再开启。
5. 在同一距离、相同手机和无线环境中与原厂 App 对比。只报告测得的改善，不承诺固定帧率、分辨率或端到端延迟。
6. 竖屏、左横屏、右横屏和全屏监看依次检查：画面完整、比例正确、控制区不遮挡构图、按钮可触达且不被安全区裁切。连续旋转时确认没有新握手或重复启流。无画面、恢复中和快门处理中也须保持布局稳定。

交付物包括源代码工程、云端测试和打包工作流、中文使用/安装说明、协议来源与已知限制，以及实际执行的验证结果。云端 IPA 和真机结果是后续独立确认的交付状态。
